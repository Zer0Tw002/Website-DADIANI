## Как сделать сайт для нового клиента (по порядку)

Делать в **копии** проекта (новая папка и новый репозиторий), чтобы демо оставалось как есть.

**1. Данные от клиента**
- Название, логотип (лучше SVG или PNG на прозрачном фоне, светлый — шапка тёмная).
- Адрес, часы работы, телефон, номер WhatsApp для брони, Instagram, 2ГИС,
  ссылки на Яндекс Еду и Wolt, процент обслуживания.
- Меню: разделы, блюда, описания, цены. Фото блюд и зала — только с правами клиента.
- Акции и тексты «О нас» — только факты от клиента.

**2. Заменить данные** (подробно — `content/README.md`)
- `src/config/site.ts` — название, контакты, ссылки, `url` сайта.
- `content/menu.json`, `content/promotions.json`, `content/about.json`.
- Фото блюд — в `assets/photos/menu/`, имена файлов — в поле `photo` блюд.
- `src/i18n/ui.ts` — слоган и описания: `tagline`, `hero.eyebrow`, `hero.slogan`,
  `booking.greeting`, `meta.*`, `og.imageAlt` (на трёх языках).
- Логотип — `assets/logo/logo.svg`, затем `node scripts/make-images.mjs` (значки и превью).
- По желанию — цвета под логотип в `src/styles/global.css` (`@theme`).

**3. Переключатели** (`src/config/status.ts`)
- `DEMO = false` — убрать пометки и кнопку «Хочу такой сайт».
- Если показываем клиенту черновик до согласия — `IS_CONCEPT = true` (плашка «Концепт-версия»).
- Когда клиент всё подтвердил — `IS_CONCEPT = false` и `NOINDEX = false`. Это само включит
  разметку «Restaurant» для поисковиков, `sitemap.xml` и ссылку на него в `robots.txt`.

**4. Проверка и публикация**
- `npm run build` без ошибок; открыть сайт на телефоне и компьютере на трёх языках.
- Казахские и английские тексты — проверить у носителя языка.
- Опубликовать на Cloudflare Pages (новый проект; сборка: Astro, `npm run build`, папка `dist`).
- После публикации: бронь (сообщение приходит клиенту), звонок, ссылки доставки,
  превью ссылки в WhatsApp/Telegram.

**5. Передача клиенту**
- Репозиторий и проект Cloudflare — на аккаунты клиента, либо в договоре прописать,
  что сайт ведёт разработчик (ежемесячная поддержка).
- В репозитории нет паролей, ключей и токенов.
- Показать клиенту `content/README.md` — как самому менять меню, цены и акции.

## Хостинг (Cloudflare Pages)
- [x] Демо опубликовано на Cloudflare Pages: https://restoran-demo-1cw.pages.dev
      (проект `restoran-demo`, репозиторий `restaurant-site-template`, ветка `main`;
      каждый push в `main` обновляет сайт автоматически). Адрес `….pages.dev` задаётся
      при создании проекта и потом не меняется — переименование меняет только подпись.
- Доступ Cloudflare к GitHub выдан только к одному репозиторию (Only select repositories).
- Cloudflare называет Pages «legacy» и продвигает Workers. Pages пока работает;
  если Cloudflare объявит его отключение — перенести сайт на Workers (статический
  сайт переносится без изменения кода страниц).
